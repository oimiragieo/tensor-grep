    Subprocess output decoding

    Production subprocess callsites choose one decoding contract from the shape of the output:

    Output Contract
    Human-facing help, errors, installer output, and stderr tails Explicit UTF-8 with replacement so malformed diagnostic bytes remain reportable.
    Machine-readable text such as JSON, NDJSON, versions, hashes, and Git framing Capture bytes and decode protocol input strictly as UTF-8. Diagnostic stderr uses replacement separately; the pip-index probe parses versions from both streams and therefore decodes both strictly. Invalid protocol bytes are a malformed result.
    Filesystem names from NUL-delimited Git or ripgrep output Capture bytes, preserve the delimiter and payload, then use os.fsdecode on each path. Use os.fsencode when the path must be hashed or sent back as bytes.
    Output ignored by the caller Keep bytes mode; do not decode streams that are used only for the return code.

    subprocess.run(text=True) uses one decoder and newline translation for both captured streams. Strict text decoding is rejected by the guard: on Windows a reader-thread exception can lose a stream instead of reaching the caller's exception handler. Capture protocol bytes and decode explicitly in the consumer. Also use bytes when stdout and stderr have different contracts or path/content bytes must remain intact. run_subprocess remains a timeout wrapper and forwards caller options; each caller still owns its output contract.

    The three pure decoders live in core/subprocess_decoding.py, so backend consumers depend on the core layer. cli/subprocess_policy.py explicitly re-exports the same function objects for existing callers and continues to own timeout configuration and the subprocess wrapper.

    The MCP rewrite subprocess helper captures bytes for both JSON/index callers and display-only diff previews. JSON remains strict, including disclosed exit-2 partial results; previews use replacement decoding. A failed command's malformed unused stdout cannot mask its exit/stderr classification. Git path bytes that the Windows filesystem codec cannot represent make the codemap census or revision evidence unavailable, rather than producing a lossy path or a false clean result.

    Classification and validation share one text-mode predicate covering text, universal_newlines, encoding, and errors. An explicit encoding enables decoding even with text=False; such strict capture is rejected. Implicit UTF-8 replacement decoding is classified as diagnostic text, rather than mislabeled as bytes.

    Subprocess options must use explicit keywords. More than one positional argument or any *args expansion is rejected before policy classification or forwarding exceptions, because positional options can hide capture and universal_newlines. The command itself may be the sole positional argument or args=.... This conservative syntax rule also applies to aliases, timeout wrappers, and generated helpers. The summary counts every active decoding spelling, not only text=True.

    The bounded static census is python scripts/check_subprocess_decoding.py. It visits statements in source order and snapshots module/import/callable aliases at each sink. Definite rebinding removes a prior alias; conditional and loop joins retain a possible subprocess binding as unresolved and reject its use. Exception handlers conservatively join the state before each statement in their try body, and finally includes possible exceptional exits. Exceptional prefix states from else reach finally and surrounding handlers, but do not feed the same try's handlers. This can reject an ambiguous call even when runtime conditions would make it safe.

    The scanner recognizes _self.subprocess injection, local module/callable aliases, the timeout wrapper, and literal Python argv (including named list aliases, list concatenation, append/extend, args=, and -X utf8 -c). It follows simple named list aliases through supported mutations. When a known possible Python -c argv becomes uncertain through a branch, dynamic replacement/concatenation/extension, or subscript assignment, that launch is rejected instead of disappearing from the census. A definite overwrite with a non--c argv clears that evidence. Explicit executable names python, pypy, their versioned forms, and Windows .exe forms are treated as Python; unresolved executable expressions, including sys.executable, remain conservatively possible. A known other executable such as git does not turn its -c configuration option into generated Python. Generated source is parsed recursively; unresolved, missing, or syntactically invalid -c payloads fail closed.

    A bounded exact-forwarder exception records the callsite identity, normalized call AST hash, **name expression, and owning function AST hash; it cannot waive another call in the same function. Fingerprints use ASTs without source locations; line/column relocation alone does not invalidate an exception or the inventory. Identity also includes the source path, qualified function, target, and duplicate-call ordinal. Synthetic violations(rows) checks only the supplied rows. Strict check_repository(rows) additionally requires the exact committed identity/fingerprint population, complete inventory record fields with unique identities, matching per-call policy and rationale, and every exception consumed exactly once with no stale entries. Line and column fields must be valid locations but are excluded from identity comparison. The CLI and production census test use strict checking. The checker also guards text=True, universal_newlines=True, encoding=..., and errors=... when they activate text decoding. getoutput and getstatusoutput implicitly capture text and require explicit UTF-8; check_output implicitly captures bytes unless decoding options request text.

    Injected module/callable aliases and explicitly aliased imports of the timeout-wrapper module join the same alias tracking. Literal scalar += updates generated-source strings; an unresolved augmentation invalidates the source rather than parsing its old value. Unresolved argv options before the selected -c are rejected because they could select an earlier payload; the unresolved executable slot itself remains supported.

    Fingerprint serialization includes the AST node type and sorted present fields, recursively retaining list order and scalar values. It normalizes only an empty type_params list, which Python 3.11 omits and 3.12 adds; nonempty type parameters, ordinary empty lists and None remain significant. This avoids interpreter-dependent ast.dump formatting. The migration compared all 72 calls and seven exact exceptions one-to-one, including generated-parent identities, and verified identical complete inventories and pins on Python 3.11, 3.12 and 3.13. Unknown future AST changes are not automatically ignored.

    python scripts/check_subprocess_decoding.py --write-inventory regenerates the per-call inventory in JSON and Markdown. The committed census currently contains 72 unique output-capable sinks, including 10 calls from the scheduled-upgrade helper in main.py and 2 from the Windows native-refresh helper. The production census test runs the scanner and pins those counts and zero violations. These are bounded syntax guarantees; the scanner does not decide arbitrary Python execution, monkeypatching, reflection, computed imports, or general data flow. Such behavior must be made statically visible or explicitly added to a reviewed bounded rule.

    Tests in tests/unit/test_subprocess_decoding_guard.py mutation-check alias rebinding and copying, branch/exception/finally paths, wrapper forwarding, decoding flags, named/generated Python argv, UTF-8 interpreter flags, and fail-closed dynamic inputs. Positive controls cover definite overwrite, Git -c, and location-only changes; negative manifest controls swap a call without changing the population size and invalidate or duplicate exact exceptions. Byte-path behavior is pinned at Git/ripgrep path consumers on platforms that expose arbitrary filesystem bytes.
